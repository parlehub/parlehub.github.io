## What this is

The marketing site for ParleHub ("The Shared Hub for Team AI Conversations"), served via GitHub Pages at www.parlehub.com (see `CNAME`). There is no build system, package manager, or test suite — plain static HTML/CSS/JS. Deployment is simply pushing to `main`; GitHub Pages serves the repo root directly.

The site is multi-page: `index.html` (home), `security.html` (security & compliance deep dive), `pricing.html` (plan comparison), `terms.html` (Terms of Service), `privacy.html` (Privacy Policy), plus the competitor comparison set in `compare/` (`index.html` hub, `parlehub-vs-claude.html`, `parlehub-vs-chatgpt.html`, `parlehub-vs-gemini.html`). Every "Sign in" / "Start free" / "Start free trial" CTA links straight to **`https://app.parlehub.com`** — the live product. There is no email-capture/waitlist form anymore; the product is live, so the CTA is always the real signup, not a "notify me" form.

The contracting entity in `terms.html`/`privacy.html` is **ParleHub LLC** (North Carolina), governed by North Carolina law; legal/privacy contact addresses are `legal@parlehub.com` / `privacy@parlehub.com`. These were confirmed by the site owner, not invented — if the entity, jurisdiction, or contact addresses ever change, update both files (and their cross-references to each other) together. These pages are a solid drafting starting point but haven't been reviewed by a lawyer — flag that if asked to substantively change liability, indemnification, or governing-law language rather than just editing prose.

### Core features to showcase

**1. Team-based shared workspace [LIVE]**
Projects contain shared conversation threads visible to every project member in real time — not per-person silos. Live presence indicators show who's viewing/typing/waiting on a response; a teammate's in-flight message and the AI's streamed reply appear live to everyone watching. Conversations support branching (edit-and-resend), rename/archive, full history search (keyword + semantic), and promoting a personal chat into a shared project. This is the core "stop running your team's AI in a thousand private browser tabs" story.

**2. Project-based budgeting for people who multitask [LIVE]**
Budgets are scoped to *projects*, not just individuals — built for people juggling several projects who need to cap spend per initiative rather than per head. Pre-flight enforcement hard-blocks a send before it would exceed the project budget (with an 80% warning), plus complementary personal (per-user) and org-wide spend caps as backstops. Users blocked by budget can self-serve request an increase, routed to admins for approve/reject.

**3. Enterprise SSO [LIVE]**
- Microsoft Entra ID (OIDC) — **[LIVE]**, verified in production. Domain-based auto-provisioning, tenant-pinned, org can enforce SSO-only login.
- Google Workspace (OIDC) — **[LIVE]**, verified in production 2026-08-08 (confirmed by the site owner; previously [SHIPPED] pending a live round-trip against a real Google tenant). Claim it on equal footing with Entra ID.
- SAML (Entra, Google Workspace, or generic/Okta) — **[ROADMAP]**, not built. Do not mention SAML.

**4. Enterprise-native file storage for security & compliance [LIVE]**
Project files can live in the org's own enterprise store instead of ParleHub's storage — files never leave the customer's tenant.
- SharePoint (Microsoft 365) — **[LIVE]**, verified against a real production tenant. Least-privilege, per-site Graph access (`Sites.Selected`), native SharePoint search, deletes go to SharePoint's own recycle bin.
- Google Drive (Shared Drives) — **[LIVE]**, verified in production 2026-08-08 (confirmed by the site owner; previously [SHIPPED] pending a live smoke against a real Drive). Auth, path resolution, native Docs/Sheets/Slides export, Drive full-text search. Claim it on equal footing with SharePoint.
- Both are Enterprise-tier only, with a two-step enable (org enables the provider → project connects a specific site/drive). The default managed storage (Azure Blob) is always available on every tier, with its own recycle bin, versioning, and inline previews.

**5. Flexible model access: two ways in — bring your own key, or use models we host [LIVE]**

**There are two access modes and copy must never imply only one exists.** An org can bring its own provider keys, use ParleHub-hosted models with no key at all, or run both at once (`AccessMode` Managed / Hybrid / BYOK). "ParleHub is BYOK" was true until Aug 2026 and is now **wrong**; a lot of older copy still says it, so check rather than copy.

- Bring-your-own-key (BYOK) — **[LIVE]**. Orgs supply their own provider API keys (stored via Azure Key Vault, never exposed). Fully working, production-quality for **Anthropic, OpenAI, and Google Gemini**; **Azure OpenAI** is also supported as a BYOK provider for Azure-native orgs. Model spend lands on the customer's own provider contract, at their rate; nothing is metered by us.
- Managed / hosted models ("use our models, no key setup") — **[LIVE]**, confirmed by the site owner 2026-08-09. Runs on Azure AI Foundry behind ParleHub's own managed identity (no static inference key), routed via `FoundryProvider`. Priced **per token**, drawn from a credit wallet the org tops up. A managed org can start a conversation with no provider account at all.
- **Governance is identical across the two modes, and this is the line to lead with, not an asterisk.** Tier spend caps, project budgets, personal and org-wide caps, the 80% warning, the pre-flight hard block, the token ledger, the project code and the CSV export all behave the same whichever way tokens are paid for. **The tier caps are budget limits, not BYOK limits** — an earlier pass wrongly labelled the Free plan's $10 as an "own-key" cap; it applies to model spend either way. Switching a project between your keys and ours changes the invoice and nothing else, which is also what makes the portability argument on the comparison pages true.
- BYOK Gemini — **[SHIPPED]** (as of ADR-024 / APP-162). Targets the Gemini Developer API (Google AI Studio key, same one-key-per-provider shape as every other provider — no separate GCP project/service-account setup). Full tool-calling support (MCP tools work over Gemini, not deferred), vision/PDF attachments, streaming. Code-complete and unit-tested; like Anthropic/OpenAI, live streaming is only exercised on the paid gated test track, not yet clicked through against production traffic — safe to market as a real, working provider, just not "battle-tested at scale" yet. Vertex AI (the GCP-enterprise auth flavor of Gemini, as opposed to this Developer-API flavor) is a distinct, not-yet-built follow-on provider — don't imply Vertex/enterprise GCP support.
- **Two things to still be careful about, now that managed models are live:**
  1. **Don't imply a broad hosted catalog, and don't name a specific hosted model without checking.** The catalog is *curated and deliberately small* — the Foundry account fronts a large menu, but only the models actually deployed are offered. Say "models we host" and let the app's catalog speak. **What you can say confidently is the category:** the hosted set reaches beyond the big three to **open-weight models a customer has no contract with and realistically never will** (confirmed by the site owner 2026-08-09; APP-178 records Llama-3.3-70B as deployed). That is the sharpest thing about hosted access and it is worth leading with, because it is the one model-access claim **no** competitor can match — Claude sells Claude, ChatGPT sells OpenAI. **The exception is Vertex AI**, whose Model Garden genuinely does serve open models, so the Gemini page must not claim otherwise; the honest distinction there is that Vertex serves them to an engineer with a Cloud project, and we serve them as a dropdown in the conversation a consultant is already in.
  2. **Don't write "we resell tokens."** Whether the underlying Azure terms permit *reselling inference* versus *bundling AI features into the SaaS* is tracked as gate G1 on APP-142 and was still open on the board as of Aug 2026. The safe framing either way is consumption-based **"models we host, charged by what you use"** — not "buy tokens from us at a markup". Confirm with the site owner before any copy goes further than that.
- The old "prepaid credits transferable across OpenAI/Anthropic/Gemini" framing was always architecturally wrong and is still wrong — hosted models run through Foundry, so don't describe hosted access as a portable credit that spends against any provider.
- Net effect, and the line the site should take: **you can bring the models you already trust and pay for, or use ours and pay for what you use, or both.** That is a genuinely stronger position than any of the three model vendors, all of whom sell only their own models on only their own terms.

## Working with this codebase

- **Shared assets, per-page markup.** `assets/tailwind.config.js` (the Tailwind Play-CDN config) and `assets/site.css` (custom CSS) are each a single file included by every page — edit once, it applies everywhere. Header, nav, and footer markup, by contrast, is hand-duplicated inside each hand-written `.html` file (there's no templating/build step for them, and copy-paste still beats adding tooling at this size). When you change the header/footer/nav, apply the same change to **all nine** hand-written pages — the 5 root pages plus the 4 in `compare/` — **and to `_layouts/default.html`**, which carries the same header/footer for the blog index, archive, and every post. Include the mobile nav row (see below) and each page's active-nav-link state (the current page's nav link/mobile-nav link is `text-parchment`, the others are `text-parchment-dim`; the `compare/` pages have no nav link of their own, so all three of theirs stay dim).
- **Logo mark.** The header icon and the small footer icon are the *real* ParleHub product logo — a `bg-gradient-to-tr from-[#005ac2] via-[#4d8eff] to-[#adc6ff]` rounded square containing the speech-bubble `<path d="M21 15a2 2 0 0 1-2 2H7l-4 4V5a2 2 0 0 1 2-2h14a2 2 0 0 1 2 2z">` — not an invented mark, and it must be byte-identical across all 5 pages (header) and all 5 footers. The favicon (`<link rel="icon">`, all 5 pages) points at `/images/grad-215x215.png`, the same mark as a pre-rendered PNG; `apple-touch-icon` points at `/images/apple-touch-icon.png`. Both were supplied by the site owner from the real app, not generated here.
- Tailwind loads from the CDN (`cdn.tailwindcss.com?plugins=forms,container-queries`), then `<script src="/assets/tailwind.config.js"></script>` sets `tailwind.config` — same load order the Play CDN requires (config script *after* the CDN script). There's no PostCSS step or npm install.
- **Mobile nav.** The desktop nav (`Security` / `Pricing`) is `hidden md:flex` in the header. Below `md`, a separate `<div class="md:hidden flex ...">` row (right after `</header>`, before `<main>`) repeats those links plus "Sign in" — without it, mobile visitors have no way to reach Security/Pricing except scrolling to the footer. Keep this row in sync with the desktop nav if links are added/removed.
- No local dev server is required for static preview, but because pages use root-relative paths (`/assets/...`, `/security/`), open them through a static file server (e.g. `python -m http.server`) rather than as bare `file://` URLs, or those paths will 404.
- **Every URL on this site is a trailing-slash directory. Never write `.html` in a link.** `_config.yml` sets `permalink: /blog/:year/:month/:day/:title/`, and because that style ends in a slash Jekyll gives *pretty* permalinks to **pages** as well as posts. So `/security/`, `/pricing/`, `/terms/`, `/privacy/`, `/blog/`, `/blog/archive/` — and `/security.html` is **not** the canonical URL any more (it forwards, see below). Writing `/security` without the trailing slash also works but costs a 301, so include the slash.
  - The five root pages (`index`, `security`, `pricing`, `terms`, `privacy`) and the four `compare/` pages each carry a small front matter block. It exists because **`jekyll-sitemap` only walks `site.pages`**, and a file with no front matter is a *static file*, invisible to the sitemap. Delete the front matter and that page silently vanishes from `/sitemap.xml` with no build error. The `compare/` pages have `permalink:` but no `redirect_from:` — they were born at their pretty URLs, so there is no legacy `.html` URL to keep alive.
  - `permalink:` in that block is the canonical URL. `redirect_from:` (via `jekyll-redirect-from`) generates a stub at the old `/security.html` URL that forwards to it, because those URLs were live, are in Google's index, and are linked from published blog posts. **Don't remove the `redirect_from` entries** — they are the only thing keeping the old URLs alive.
  - Historical note so nobody "fixes" this backwards: these pages originally had *no* front matter and served at literal `/security.html` URLs. Both changed in Aug 2026.
- **The canonical host is the apex `parlehub.com`, with no `www.`.** `CNAME` contains `parlehub.com`, and `www.parlehub.com` 301-redirects to it. (This was the other way round before Aug 2026; a `www.` link still resolves, it just costs a redirect, so don't write one.) Prefer root-relative paths for internal links, and `https://parlehub.com/...` when an absolute URL is genuinely needed. **`_config.yml`'s `url:` must match `CNAME`** — `jekyll-sitemap` stamps it onto every `<loc>` and onto `robots.txt`, so a mismatch silently publishes a sitemap whose URLs all redirect.
- No linter, formatter, or test command is configured. Verify changes visually in a browser (Playwright + a static server works well for this, since there's no project-specific run skill).
- Every CTA points at the literal string `https://app.parlehub.com` (root, no subpath) — the app's actual `/signup` or `/login` routes weren't confirmed, so don't invent deep links. Ask before adding one.
- **`llms.txt`** (root, served at `/llms.txt`) is a hand-maintained plain-text summary of the product and a link index of every page and blog post, for LLMs and AI crawlers. It has **no front matter on purpose** — Jekyll copies it through verbatim as a static file, and running it through Liquid would only risk mangling the text. Nothing generates it, so **when you add or remove a page or a post, or change a plan/feature claim, update `llms.txt` too** or it silently drifts. Every accuracy rule in this file binds there as well (two model-access modes, no SAML, no SOC 2, no named hosted models, no "we resell tokens").
- **`<main>` must not have `overflow-hidden` on a page with a sticky element.** `index.html`'s `<main>` has `class="relative overflow-hidden"` to clip the hero's decorative glow/hub-diagram; that class was originally copy-pasted onto every page. On `terms.html`/`privacy.html`, which use a `position: sticky` table-of-contents sidebar next to the long-form legal text, `overflow-hidden` on an ancestor silently breaks the sticky behavior (it stops sticking after ~1 viewport height, with no console error). Those two pages' `<main>` is just `class="relative"` — don't "fix" that back to match the other pages.

### Comparison pages (`compare/`)

Head-to-head pages against the model vendors' own team products: `/compare/` (hub), `/compare/parlehub-vs-claude/`, `/compare/parlehub-vs-chatgpt/`, `/compare/parlehub-vs-gemini/`. Rules these pages are built to, because getting a competitor claim wrong costs more than the page earns:

- **Every claim about another product is sourced from that vendor's own documentation**, linked in a "Sources" card at the foot of the page, with the month it was checked stated in the hero *and* in the sources card. Both vendors ship fast: Anthropic and OpenAI each added org/group/user spend caps and analytics in 2026, so **never write "they have no budgets"** — the true and stronger claim is about the *axis* (they budget by person or group; we budget by project, and carry the customer's own expense code into the export).
- **The Gemini page states a product gap on purpose, and it must keep doing so.** We connect Gemini through the **Gemini Developer API** (AI Studio key). **Vertex AI is not a supported provider.** A page carrying "Vertex AI" in its title invites a reader to assume otherwise, so the boundary is stated twice: in the "Read this first" card near the top, and as the first entry in "Where Google is the better buy". **Do not soften or remove either one** while Vertex is unbuilt; a GCP-native buyer discovering it after signing is worth more damage than the page earns. If Vertex ships as a provider, update both spots and the "How we connect to Gemini" table row together.
- **Facts as of Aug 2026, the ones the tables rest on:** Claude budgets scope to org, group (RBAC), and individual user, with alerts at 75%/95%, the current turn completing before usage is limited; chats inside a shared Claude Project are **private to their author unless manually shared**, while knowledge and instructions are shared. ChatGPT credit limits scope to workspace, group, and user, monthly, with export to financial systems; shared projects make files and chats visible to project members but are **not live** (no presence, no co-editing a conversation). Google is the nuanced one: Cloud Billing **does** budget per project and now has **spend cap budgets in preview** that genuinely block new usage, so never write "Google can't cap spend" — the true distinctions are that the unit is a *Cloud* project rather than a client engagement, enforcement runs on estimated cost and is not instantaneous, in-flight requests complete, and a cap covers one project and one eligible service. Sharing a Gemini Enterprise conversation produces a link to the content **as it stood**, with later turns invisible to the recipient. Re-verify before editing a cell.
- **Each page carries a "Where <competitor> is the better buy" section, and it must stay honest.** Deleting that section to make the page win is not an option. Its content changed on 2026-08-09 when hosted models went live: the old standing entry ("they give you one vendor and one invoice, we need a key") **no longer applies to any of the three** and was removed. What replaced it is specific per vendor, and each is a real, checkable advantage: **Anthropic** gives you their whole first-party model line on the day it ships, where our hosted catalog is a curated set someone chose; **OpenAI** covers ordinary chat in the seat, so per-head cost is flat and nobody watches a meter; **Google** puts a quota in the seat before metering starts and lives inside Docs and Gmail. If you find yourself unable to name a genuine advantage for a competitor, look harder rather than dropping the section.
- **Never write that a competitor "includes" model usage in the price.** An earlier draft put "Yes" against a *Model usage included in price* row for Claude; the site owner caught it. The row title was the actual bug, because it forces a yes/no onto something that is not binary, and all three vendors meter. As documented in Aug 2026: **Anthropic** prices Claude Enterprise "per seat, usage-based" with no stated included allowance; **Google** puts a quota on a Gemini Enterprise seat and charges consumption beyond it; **OpenAI** covers ordinary chat in the seat and meters heavier agentic use against a purchased credit pool. The row is now **"How model usage is paid for"** with a descriptive cell per product. The honest frame, and the better one for us, is *whose meter and whose rate*, not included versus not included: on ParleHub the spend lands on the customer's own provider contract and our subscription is separate.
- **Trademark line in the sources card** ("X is a trademark of Y. ParleHub is not affiliated with or endorsed by Y."). Keep it.
- The site-wide accuracy rules still bind here, and two bite hardest on a comparison page: **never mention SAML** (both competitors have it, we do not, and the honest framing is to describe our Entra ID and Google Workspace OIDC support without opening the comparison), and **no SOC 2 row** — we have no report, the phrases that paper over that are banned, and a row inviting the question belongs in a conversation rather than on a page (see `pain-point-map.md` in the private marketing repo).
- **The portability section is the lock-in argument, and it has a precise boundary.** What is true and [LIVE]: model switching is per conversation, providers are connected at org level with your own keys, and everything a team builds (projects, threads, files, budgets, project codes, roles, ledger, audit trail) lives in ParleHub rather than in the provider, so changing provider is a settings change and not a data migration. **Do not escalate that into a one-click "migrate my org" wizard, a bulk re-run of old conversations on a new model, or automatic routing to the cheapest provider** — none of those are claimed, and the last one contradicts the standing "budgets hard-block, switching is deliberate" rule. If the product later ships an explicit bulk provider-move action, name it here before naming it on the page.
- The "two ledgers" graphic (budgeted-by-person/workspace vs budgeted-by-project, with `ENG-4417` and a verdigris meter) is inline HTML, no new CSS, and is the pages' signature element. It reuses the hero card's project-code vocabulary on purpose. It is `aria-hidden` decoration; the argument it illustrates is always written out in the prose beside it.

### Design system

The design is a deliberate departure from generic "dark SaaS" — themed around ParleHub's name (a conversational **hub**) and its ledger/governance angle (budgets, audit trail), rendered as a control-room-meets-accounting-ledger aesthetic. Don't casually revert to generic gold/brass or invented palettes; `primary` specifically must stay matched to the real product below.

- **Color** (defined in `assets/tailwind.config.js`): `ink` (#0b0e17, background — a cooler, more "control room" near-black, not neutral), `ink-raised`/`ink-line` (surfaces/borders), `parchment`/`parchment-dim` (warm off-white text, evokes ledger paper rather than clinical white), `verdigris`/`verdigris-dim`/`verdigris-bright` (secondary accent — a muted teal-green, reserved for budget/ledger/audit contexts specifically, not used everywhere, to keep it meaningful).
- **`primary`/`primary-bright`/`primary-dim` (#4d8eff / #7fabff / #3e5f8f) is the real app.parlehub.com brand blue, not a design choice to riff on.** An earlier pass of this site used an invented gold/brass accent; the site owner corrected that because it didn't match the actual product. The blue values were obtained by loading real screenshots of the live app (`images/modelconnection.png`, `images/billing.png`) into a headless browser, drawing them to a `<canvas>`, and reading exact pixel colors with `getImageData` — not eyeballed. Confirmed data points: the logo's gradient is `from-[#005ac2] via-[#4d8eff] to-[#adc6ff]` (used literally in the header/footer logo mark and the hero's `.primary-text` gradient), the app's solid interactive-blue (checkboxes, avatars) samples to `#155dfc`, and its sidebar/dark surface samples to `#0f172a` (Tailwind `slate-900`). If asked to adjust brand colors again, re-derive them the same way (sample the real app or ask for a current screenshot) rather than picking an aesthetically-pleasing color — this is a real brand, not a free palette choice.
- **Type**: `font-display` (Fraunces, a characterful serif) for headlines, `font-body` (Inter) for body copy, `font-mono` (IBM Plex Mono) for eyebrow labels, prices, and any "ledger figure" (token counts, budget numbers, table data) — the mono face is doing real conceptual work (money/data reads as a ledger entry), not just decoration.
- **Signature element**: the hero's hub diagram (`index.html`, `.hub-diagram`/`.hub-node`/`.hub-center` in `assets/site.css`) — a central card (mini shared conversation + presence avatars + a budget meter, encoding collaboration *and* budgeting at once) with blue wire-lines radiating to 8 labeled nodes (Anthropic/OpenAI/Gemini/Azure OpenAI on one arc, SharePoint/Google Drive/Entra ID/Google Workspace on the other). Built with an inline SVG (percentage-based `viewBox="0 0 100 100"`) for the lines and Tailwind arbitrary-value classes (`top-[10%] left-[50%]`) for node positions — this only appears once, at full size, in the hero; don't recreate the full orbit elsewhere. It collapses to a static stacked card + wrapped pill list below `md` (there's a separate `md:hidden` block for this — the absolute/orbit version is real content, not decorative, so it needs a working non-JS fallback, not just `overflow: hidden`). Entrance animation respects `prefers-reduced-motion` (see the media query at the bottom of `site.css`).
- **Ledger table** (`pricing.html`): sets the whole table (labels included) to `font-mono` via a `.ledger-table td/th` rule — a `font-body` utility class was tried on the label column but loses the CSS specificity fight against that rule, so the whole row ends up monospace. Left as-is; it reads fine as an intentional "everything in the ledger is mono" choice, but know why before "fixing" it.
